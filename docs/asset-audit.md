# Asset audit and extraction boundary

The authoritative local teaching entry was identified through its frontmatter,
workspace instructions, invocation guide and runtime enablement code, rather
than its filename alone. Its name is `pedagogical-readability`, with the
structured alias `pedagogical_readability`. The requested shorter spelling was
not an existing formal entry.

The current skill was untracked in the shared workspace. An early 8,855-byte
snapshot and a 15,455-byte applied successor survive in the similarity/quadratic
handbook's local workflow artifacts. An application manifest identifies the
successor as applied locally. The current 16,076-byte source differs from that
successor only by the later Writer Advisory. Its complete SHA256 and reversible
packaging adaptation are in [the preservation record](preservation.json).

The Math I manuscript is a separate repository at commit
`029e8b52b5175dd825a86a94da32426a57bda3a4`. Its LaTeX source supplied topic
selection and fact checks for this evaluation. The earlier readability
experiments were hosted by the similarity/quadratic handbook, not Math I.
Historical experiments are design background; they are not pooled into the new
study. No private chat archive or complete manuscript was transferred.

| Source mechanism | Main role | Overlap and extraction decision |
| --- | --- | --- |
| Technical review, premise preservation and final guard | Rigor / Workflow | Keep mandatory protections in the original skill |
| Hidden inference audit, symbol identity, representation relations, H2/H3 repairs | Rigor / Comprehensibility | A valid derivation can still omit a reader's necessary bridge; retain both roles rather than call this a pure correctness mechanism |
| Reader prerequisites, conceptual connections, motivation and concrete representations | Comprehensibility | Extract adaptable judgment guidance; preserve the original too |
| Writer Advisory: operation-led explanation, reordered existing content, optional strategies | Comprehensibility | Generalize strategy selection without converting advice into mandatory templates |
| Example objectives, practice, hidden answers and teach-back | Pedagogy | Keep in teaching skill; exclude from general explanation skill |
| Continuous-reading review, exact quotations, local repair ownership, bounded retry and checkpoints | Workflow | Retain original runtime behavior; do not make it a dependency of the new skill |

The teaching entry had only two files but depended on substantial external
runtime code, schemas, model configuration, tests and documentation. Copying it
unchanged into a new folder would leave broken references. With the owner's
approval, packaging changes only those references and adds a dependency notice;
reversing the recorded edits reconstructs the original bytes. No mandatory
review, advisory status, teaching trigger or repair budget is weakened. Shared
runtime code is neither bundled nor relicensed.

The standalone skill targets the reader's knowledge starting point, dependency
order, conceptual links, abstraction changes, explanation form and avoidable
cognitive load. It does not inherit proof verification, exercise design, PDF
production or a review graph. Duplication between the two skills is intentional:
independent use and behavior preservation take precedence over deduplication.

The owner confirmed copyright ownership and MIT authorization for the skill
content. Mathematical and technical fact packs are original restatements with
[provenance](../evaluations/task-provenance.json); third-party prose and whole
handbooks are excluded. Original files and seven key dependency snapshots remain
unchanged locally. A byte comparison is stronger preservation evidence than a
claim based only on similar wording, but it does not by itself establish runtime
behavior or a learning benefit.
